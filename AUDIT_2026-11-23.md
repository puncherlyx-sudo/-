### 3.1 Запасной «бэктест» не считает по рынку [ПРОВЕРЕНО]
`src/lib/localAnalyticsEngine.ts`, функция `runLocalPortfolioBacktest` не принимает цены и свечи. Процент побед она берёт из хэша названия стратегии и таймфрейма (`hashString`, `seededUnit`) и **добавляет бонус по тарифу стратегии**: `tierBonus = 5.8` для MAX-стратегий и `3.2` для PRO, затем ограничивает результат от 46 до 76 %. Прибыль, фактор прибыли и просадку она получает из этого процента формулами, кривую капитала рисует синусом. Это генератор правдоподобных чисел, а не бэктест.
Её вызывает `StrategyPnlChart.tsx` (строка ~234), когда запрос к серверу не удался. Над результатом при этом остаётся надпись «Бэктест по реальным свечам OHLCV», рядом «Локальный расчёт (OHLCV модель)» и «Комиссия 0.08% учтена». Для запасного режима это неверно.
Для сравнения: серверный `runStrategyPortfolioBacktest` берёт реальные свечи через `getMarketCandles` и считает сделки по ним — так и должно быть.
Это же касается запасных режимов сканера и «Sentiment» (`runLocalLiveScanner`, `buildLocalSentimentReport`); как они подписаны и из чего считаются, я не проверял [НЕ ПРОВЕРЕНО].

### 4.2 Правила русского текста для Vernier (применил принципы humanizer и antialgorithm)
1. Один термин — одно слово. Решите: «сигнал» или «идея», «кредит» или «запрос», «радар» или «скринер», и держитесь.
2. Жаргон объясняем при первом упоминании коротким пояснением в подсказке (например, FVG: «разрыв цены между свечами»), в самом тексте — по-русски там, где есть привычное слово.
3. Каждое утверждение либо проверено (число, дата, источник), либо звучит как наблюдение («обычно», «бывает»), либо исчезает.
4. Предложение — одна мысль, глагол в начале, без «позволяет», «обеспечивает», «предоставляет».
5. Тире — только там, где без него неясно. Восклицательных знаков нет.
6. Обращение «вы», строчными. Без «наш помощник на базе Gemini расскажет…».
7. Ошибки пишем как человек: что случилось, что делать дальше. Без «Произошла непредвиденная ошибка».

## 5. Дизайн (метод antialgorithm: сначала назвать «обычный ответ», потом уйти от него по причине из проекта)

**Обычный ответ здесь** [ПРОВЕРЕНО по `src/`]: тёмно-синий фон `#0B0F17`, изумрудно-янтарные градиенты и свечение. В коде 75 градиентов (`bg-gradient-to`), 7 световых теней, 1524 упоминания `emerald-` и 688 `amber-`, 33 стеклянных размытия, 151 скругление `rounded-2xl/3xl`. Так выглядит почти каждый «крипто-терминал на нейросети».

**Причина для другого решения** — само название: нониус — измерительная шкала. Предлагаю строить внешний вид из шкал и совпадений, а не из свечения. Каждое решение ниже имеет причину из проекта.

1. **Совпадение таймфреймов как нониус** (причина: в `MultiTimeframeStrip` уже есть 15м/1ч/4ч/1д). Две линейки с разным шагом; тик, где деления совпали, становится акцентным. Совпадение = «таймфреймы согласны». Это единственное место, где допустим акцентный цвет бренда. Условие: подсветку включает только реальная проверка (направление тренда на всех кадрах совпало), а не оформление.
2. **Поверхности как приборная панель**: плоские панели, тонкая сетка 1 px с шагом 4/20 px при прозрачности 3–4 % только под графиком, без свечения вокруг карточек. Цвет несёт смысл: зелёный и красный только для прибыли и убытка; янтарь только для «внимание»; бренд-цвет только для совпадения шкал.
3. **Шкалы вместо круглых индикаторов**: уверенность сигнала, использование кредитов, лимиты тарифа рисуем линейкой с делениями, а не градиентной полосой.
4. **Цифры**: моноширинные табличные (JetBrains Mono уже в проекте) везде, где есть деньги и проценты; выравнивание по разряду, чтобы колонки читались.
5. **Движение**: деления «защёлкиваются» пружиной, когда значение найдено; убрать общее «всплытие» карточек; уважать `prefers-reduced-motion`.
